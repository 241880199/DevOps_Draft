两次失败信息相同：

```text
success: Missing trace_id
wrong-output: Missing trace_id
invalid-candidate: Changed CMD candidate was not rejected before building
build-failed: Missing trace_id
runtime-timeout: Missing trace_id
```

根因不在 Docker 网络，而在 `prepare_candidate` 的基线比较：

```python
# 修复前
if original[0] != proposed[0].split("@", 1)[0]:
    raise ValueError("Candidate changed the original base image tag")
```

`original[0]` 是 broken fixture 的完整 `FROM` 行；本组为走镜像站，把 broken fixture 也改成了 `...python@sha256:f82c…`，因此它不会被去掉 digest，而候选侧会去掉 digest，两边永远不相等。服务容器在 `auto-build` 开始前就返回 `{"status":"FAILED","error":"Candidate changed the original base image tag"}`，所以 `run_e7_b_gate.py` 读不到 `trace_id`。

修复：

```python
if original[0].split("@", 1)[0] != proposed[0].split("@", 1)[0]:
    raise ValueError("Candidate changed the original base image tag")
```

两边都只比较镜像名/tag，digest 仍由各自的 `FROM` 保留。新增回归测试后，服务单测 `25 passed`（`work/build-03`），本地五场景门禁 `passed: true`（`work/e7-debug`）。

CI 的失败/恢复演示、分支保护和最终合并记录尚未执行；接手步骤见 `docs/B组后续任务交接.md` 第 5.3 节。

## 故障与限制

### 环境故障（不是目标失败）

1. **Docker Hub 直连超时**：服务镜像构建首先解析 `# syntax=docker/dockerfile:1` 时访问 `registry-1.docker.io` 超时。处理：删除该前端指令；本次 Dockerfile 不使用需要该前端的语法。
2. **基础镜像直连慢**：把 `services/draft/Dockerfile` 的 `BASE_IMAGE`、`DOCKER_CLI_IMAGE` 和候选的 `FROM` 改为 `m.daocloud.io` 镜像站路径，**digest 保持不变**；已预先拉取并核对 digest。
3. **`deb.debian.org` 下载停滞**：候选第一次构建在 `apt-get update`/下载阶段停滞超过 10 分钟，保留在 `work/e5-01/attempts/candidate-build-attempt1-deb-debian-stalled.log`；改用阿里云 Debian 镜像后，同一候选的 `apt-get` 层约 203 秒完成。该次停滞不计为目标失败，也不计入最终成功证据。
4. **CI 发现的基线比较 bug**：`prepare_candidate` 只把候选侧去掉 digest，没有把 broken fixture 侧也去掉；本组把 broken fixture 改成 digest 固定后触发误判。修复为两边都 `split("@")[0]`，并新增 `test_digest_pinned_baseline_compares_image_name`。这是**代码 bug**，不是环境故障；修复后本地五场景门禁通过。

### 限制

- 本次只复现单个已知答案样例，没有复现论文的 35 个项目、5 种语言和 80% 成功率等批量统计；
- 候选是单轮生成与选择，没有执行多轮迭代终止策略；
- 候选的人工镜像重写属于本组网络适配，不是模型原始回复的一部分；
- 没有调用外部模型 API，模型标识来自本次客户端环境，无法给出论文中的 temperature 等采样参数；
- E6 尚未执行；E7 只完成了本地五场景门禁预跑，CI 的失败/恢复/分支保护尚未执行；因此本报告对 E5 下完整结论，对 E7 只下“本地预跑通过”的结论。
