### 2. 固定 MD 输入

`fixed-md.json` 是固定输入（E12 才改为消费真实增量报告）：`schema_version=e11e12-1`、`kind=fixed-md`、`commit=2fe9a507...`、`status=SUCCEEDED`。`pipeline.check_envelope()` 校验版本、commit、状态与类型后，才把 `data` 交给 `lab.patch()`。`repair.json` 记录输入报告 artifact 的 URI/SHA256，保证后续可追溯。

### 3. 补丁与验证

`patch()` 只处理 MISMATCH 中的 MISSING，保留 REDUNDANT。生成的 `candidate.patch` 唯一变化是：

```diff
-main.o: main.c unused.h
+main.o: main.c unused.h config.h extra.h
```

`repair-plan.json` 为两条 `direct` 风格编辑：`config.h`、`extra.h` 都落到 `main.o` 规则行。`validate()` 在隔离沙箱中依次检查：

```json
{"accepted": true,
 "checks": {"patch_applies": true, "build": true, "test": true, "header_change": true, "no_missing": true},
 "error": null, "source_unchanged": false, "rollback": false}
```

`source_unchanged=false` 是预期行为：五项全过后，沙箱中通过验证的 Makefile 写回 target 工作副本；固定样例仓库本身不变（`sample-Makefile.before-patch` 与 target 工作副本修改前的字节一致）。

### 4. 动态重检

`patch` 后对 target 工作副本再跑 `full_check()`。`recheck.json` 的 `data.findings` 只有 RD `main.o←unused.h`，没有 MISSING；其 `commit` 仍为 target，`patched_makefile_sha256` 记录写回后的 Makefile 哈希。这证明修复消除 MD 且没有把 RD 一律删除。
