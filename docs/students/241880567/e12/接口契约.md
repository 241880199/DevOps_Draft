# E12 外接报告契约

在 `e11e12-1` 基础上，`mode=e12` 可选传入：

|字段|类型|要求|
|---|---|---|
|`incremental_report`|string|JSON 文件路径，必须位于 API 服务器的 `/course/data` 下|
|`incremental_report_sha256`|string|报告文件的 64 位十六进制 SHA256|

报告 envelope 必须满足：

```json
{
  "schema_version": "e11e12-1",
  "kind": "incremental-check",
  "status": "SUCCEEDED",
  "commit": "<target_commit>",
  "data": {
    "commit": "<target_commit>",
    "findings": []
  }
}
```

消费方在修复前执行：

1. 文件内容哈希校验。
2. schema、kind、status、envelope commit 校验。
3. `data.commit` 校验。
4. 与 target 本地全量 findings 对照。
5. 将上游 `job_id/trace_id/kind/sha256` 写入本轮 `incremental-check` 的 `provenance`。

错误码：

|错误码|含义|
|---|---|
|`INVALID_REPORT_SHA`|缺少或格式错误的 SHA256|
|`ARTIFACT_HASH_MISMATCH`|报告内容与 SHA256 不一致|
|`ARTIFACT_TYPE_MISMATCH`|报告 kind 不是 `incremental-check`|
|`STALE_REPORT`|envelope 或 payload 属于其他提交|
|`FINDINGS_MISMATCH`|外部报告与 target BuildChecker 全量对照不一致|
